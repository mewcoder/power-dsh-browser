## Chromium 页面测试

macOS 自动尝试标准 Chrome/Chromium 应用位置，其他位置通过 `CHROME_PATH` 指定可执行文件。运行 `npm run test:chromium`。

脚本使用受控的 [表单页面](../test/fixtures/form.html)，检查真实 DOM 的可见标签快照、原生输入覆盖已有文本、点击提交后的渲染状态、替换元素后拒绝旧引用、文本域填写、真实 PNG、视口滚动和完整导航后旧文档引用失效。

第九项在网页提前注册 window capture 监听器后，确认批注控制器的固定 hover/pick 查询不触发这些监听器；等待 unlock 确认后捕获层被移除，原生点击恢复。输入通过测试浏览器 CDP 执行，不直接调用 Electron webview。

## React 界面测试

运行 `npm run test:ui`。它编译实际组件，在隔离 Chromium 中以真实鼠标和键盘操作地址栏、标签栏与 Host 拾取覆盖层。测试只替换 ElectronPage 和会话服务的环境适配器，不另画一套浏览器界面。

- 核对 400/720px、浅色/深色的新标签页和批注布局：根节点、页面和工具栏均无横向溢出。
- 验证新建、切换、关闭标签后页面文字保留。
- 通过真正的 Host 覆盖层点击选择，确认网页提前注册的捕获监听器没有收到原手势。
- 选取后调用只读 status/tabs.list，批注目标、未发送文本保持；插入草稿保留已有文字与引用片，发送计数为零。
- 结束批注后，普通点击恢复网页行为；真实 Broker 能路由到实际 PageRunner 和页面快照。
- 本轮 consoleErrors 为空；截图、布局尺寸与源码 SHA256 写入忽略的验证目录。

首次运行下载固定版本 React/ReactDOM 18.3.1 UMD，仅缓存于忽略的开发验证目录，并校验固定 SHA256；它们不加入项目依赖或插件分发。临时 Chrome profile、loopback 服务只用于测试，报告确认浏览器与服务均已退出。这不是替代 DSH GUI，也不证明真实 Electron 焦点和宿主编辑器实现的全部行为。

## Desktop 实际证据

- 经用户明确授权，0.1.0 通过原生管理器安装启用，完成导航、快照、原生填写、点击提交、读取提交结果、截图进入模型与停止控制。
- 0.2.0 经原生管理器移除旧包再安装启用，之后继续使用同一项目的本地链接。0.2.1 构建完成后，原生清单确认链接包版本为 0.2.1 且 enabled/installed 为 true。没有手写 profile、修改宿主发行包或运行第三方桌面补丁。
- 用户打开新版面板后，工具确认真实 Desktop 的 MDN 标签。另建受控表单标签，填写姓名后切回 MDN、再切回表单，提交结果仍包含原文字，证明 guest 状态保留。
- 有意携带旧表单 tabId 在另一标签发出无害滚动，得到 `STALE_TAB`；切回表单后复用旧代次，得到 `STALE_DOCUMENT`。重新快照后点击正常。
- 用户随后提交本插件产生的完整批注卡片，目标是受控页面的 `input#name`，URL、标题与结构摘录正确，证明真实元素引用已能到达当前聊天。空表单 text 字段符合不采集输入值的策略。该证据不单独证明剪贴板路径、原有引用片保留或按钮选取不误触。
- 再次在真实 guest 导航受控表单、读取快照并返回清晰页面截图。一次空白页捕获产生黑色图片，不计为页面截图通过；工具随后确认那时确实为 about:blank。
- 检查中一次关闭已消失的旧标签返回 `TAB_NOT_FOUND`，新列表确认面板已成为另一新标签；没有误关闭新标签或退回操作别的页面。
- 系统禁止自动桌面辅助访问，且整窗截图无法生成；没有假称完成整个 Desktop 外壳的像素截图。上文界面图片来自隔离的实际 React 渲染，网页截图来自真实 guest。

## 尚未逐项实测

真实 Desktop 中多窗口/多会话同时操作、完整卸载后的资源统计、不同系统主题和语言、剪贴板、长时间卡住、批注插入时既有引用片及复杂焦点路径，仍需进一步验收。受控验证不能替代这些系统行为。

当前是一版可用的浏览器、内部多标签与单目标批注实现；不宣称已经拥有 Codex 的完整 AX/iframe/Shadow DOM、批注历史、批量标记、样式调整、完整 Agent 光标动画或定制网络后端。
